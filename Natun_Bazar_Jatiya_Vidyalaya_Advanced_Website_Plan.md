# Natun Bazar Jatiya Vidyalaya

## Advanced School Website --- Demo Planning & Development Blueprint

**Prepared by:** Handshake Co. --- Web Development & Software Solutions\
**Website purpose:** A school-specific, high-quality demonstration
website to present to the school principal and discuss a possible
website development project.\
**Document status:** Planning blueprint --- not an approved school
brief.

------------------------------------------------------------------------

## 1. Project vision

Create a modern, trustworthy, mobile-first school website concept for
**Natun Bazar Jatiya Vidyalaya**, Lanka, Hojai, Assam.

The demo should look and feel like a professionally developed school
website, not a generic template. It should help parents and visitors
quickly understand the school, explore academic information, find
admission guidance, read notices, and contact the institution.

The website must also demonstrate the value of an advanced website:
editable content, admission enquiry management, notice management,
gallery management, and an administrative dashboard concept.

**Important:** This is a proposal/demo made by Handshake Co. It is not
the school's official website and must not imply that the school has
commissioned, approved, or published it. Do not publish it under a
school-owned domain or present placeholder content as confirmed facts.

## 3. Website goals and target visitors

### Primary goals

1.  Establish a professional online identity for the school.
2.  Make essential information easy to find on mobile phones.
3.  Help parents understand admission steps and submit enquiries.
4.  Publish school notices and announcements in one place.
5.  Present academics, activities, staff, and campus information once
    verified.
6.  Give authorized school staff an easy way to update content.
7.  Demonstrate how an advanced website can reduce manual communication
    and repeated enquiries.

### Target visitors

-   Parents and guardians
-   Prospective students
-   Existing students
-   Teachers and staff
-   Community members
-   Visitors seeking admission or contact information

## 4. Brand and visual direction

### Recommended visual style

-   **Personality:** welcoming, credible, academic, community-oriented,
    clear.
-   **Primary palette:** deep navy and medium blue.
-   **Supporting palette:** white, warm off-white, and restrained golden
    accent.
-   **Typography:** highly readable sans-serif font; strong headings and
    comfortable body text.
-   **Layout:** generous whitespace, clear content hierarchy, consistent
    cards, simple icons, accessible contrast.
-   **Photography:** authentic school building, classroom, students'
    activities, events, and staff photographs only after permission.
    Until then, use neutral education-themed demo imagery and label it
    as illustrative.
-   **Logo:** use the school's official logo only after receiving it.
    Until then, use a clean text-based school-name treatment; do not
    invent an official emblem, crest, or motto.

### User experience

-   Responsive from small mobile screens to desktop.
-   Sticky or clearly accessible navigation.
-   Prominent admission enquiry and contact actions.
-   Notice/announcement strip on the home page.
-   Fast loading and compressed images.
-   Keyboard-accessible menus and forms.
-   Clear labels, validation messages, and readable text.

    feasible.

## 9. Technical and quality requirements for Antigravity

Antigravity should be instructed to build a polished, maintainable web
application. The exact technology can follow the existing project setup,
but a suitable modern stack is:

-   Next.js / React
-   TypeScript
-   Tailwind CSS or equivalent design system
-   Reusable components
-   Responsive image handling
-   Form validation
-   Accessible navigation and semantic HTML
-   SEO metadata and sitemap
-   Environment variables for any future integrations
-   Clear separation between public pages and admin demo

### Quality checklist

-   [ ] No broken links or buttons.
-   [ ] No horizontal overflow on mobile.
-   [ ] All forms have labels and validation.
-   [ ] Images have useful alt text.
-   [ ] Good colour contrast and keyboard navigation.
-   [ ] Pages load quickly.
-   [ ] Titles and descriptions are page-specific.
-   [ ] No fake testimonials, ratings, awards, or statistics.
-   [ ] No real student or staff personal data in demo.
-   [ ] No credentials, secrets, or API keys in source code.
-   [ ] Admin demo is not exposed as a real production system.
-   [ ] Demo disclaimer is visible.

## 10. Suggested build phases

### Phase 1 --- Discovery and content structure

-   Confirm name, address, classes, curriculum, logo, contact details.
-   Finalize sitemap and page content.
-   Identify all content that remains placeholder.

### Phase 2 --- Visual design

-   Create colour, typography, spacing, navigation, cards, buttons.
-   Design desktop and mobile layouts.
-   Review home page before building all pages.

### Phase 3 --- Public website

-   Build Home, About, Academics, Admissions, Notices, Gallery, Staff,
    Contact, Privacy.
-   Add responsive interactions and demo content.

### Phase 4 --- Admin dashboard prototype

-   Build dashboard navigation and sample management screens.
-   Demonstrate notice, gallery, page content, and enquiry management.
-   Clearly distinguish working prototype interactions from future
    integrations.

### Phase 5 --- Testing and presentation

-   Test mobile, tablet, and desktop.
-   Check accessibility, links, forms, and page speed.
-   Remove accidental invented claims.
-   Confirm every school-specific fact.
-   Prepare a short walkthrough for the principal.

### Phase 6 --- After school approval

Only after written approval and requirements sign-off:

-   Replace demo content with school-approved content.
-   Agree domain ownership and hosting.
-   Implement production authentication and role permissions.
-   Configure secure enquiry delivery/storage.
-   Set backup, maintenance, privacy, and data-retention processes.
-   Obtain permission for photos and documents.
-   Test and obtain school sign-off before launch.

## 11. Suggested demo presentation flow

Use this order when showing the principal:

1.  Open the home page on a mobile phone to show the responsive design.
2.  Explain how parents can find school information and admission
    details.
3.  Open Notices and show how announcements can be organized.
4.  Show the Gallery and Staff sections using sample placeholders.
5.  Submit a sample admission enquiry and explain the intended workflow.
6.  Open the admin dashboard concept and show how staff could update
    notices and content.
7.  Ask the principal which features are most useful and what should be
    customized.

Keep the presentation focused on the school's needs. Do not overwhelm
the principal with technical details.

## 15. Final recommendation

complete, school-specific experience rather than a generic agency
portfolio.

dashboard demonstration. Keep the school facts honest and visibly mark
what needs confirmation. Once the principal is interested, collect the
official content and prepare a final scope, timeline, and one-time
development quotation.
